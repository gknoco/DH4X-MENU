Visão geral

Todas as chamadas usam POST com corpo JSON e o cabeçalho Content-Type: application/json.

Base URL

https://geradorln.lovable.app
A validação é feita 100% no servidor. O tempo da licença não começa na criação da key, e sim na primeira chamada válida a /validate. O aparelho que ativa a key fica vinculado a ela pelo hwid.

POST/api/public/key/validate

Valida e ativa a key no primeiro uso, vinculando o HWID do aparelho. Chame ao abrir o app, na tela de login.

Requisição

{
  "key": "A0281N-IQM1B7SIB--U1M81",
  "hwid": "id-unico-do-aparelho"
}

Resposta (200 OK)

{
  "valid": true,
  "key": "A0281N-IQM1B7SIB--U1M81",
  "duration": "1d",
  "hwid": "id-unico-do-aparelho",
  "activated_at": 1756944000000,
  "expires_at": 1757030400000,
  "seconds_left": 86400
}

Timestamps em milissegundos (Unix). Em keys lifetime, expires_at e seconds_left vêm como null.

POST/api/public/key/status

Somente leitura (heartbeat). Não ativa nada. Chame periodicamente (por exemplo, a cada 60 s) para detectar pausa, expiração ou troca de aparelho.

Requisição

{
  "key": "A0281N-IQM1B7SIB--U1M81",
  "hwid": "id-unico-do-aparelho"
}

Resposta (200 OK)

{
  "valid": true,
  "key": "A0281N-IQM1B7SIB--U1M81",
  "duration": "1d",
  "expires_at": 1757030400000,
  "seconds_left": 84210
}

Se a key ainda não foi ativada via /validate, a resposta é not_activated.

Erros

Toda falha retorna "valid": false e o motivo em "reason":

{ "valid": false, "reason": "expired" }
  • invalid_key404A key não existe.
  • paused403A key foi pausada pelo administrador.
  • expired403O tempo da licença acabou.
  • hwid_mismatch403A key está vinculada a outro aparelho.
  • not_activated403Chamada a /status antes de /validate.
  • bad_request400Corpo inválido ou campos key / hwid ausentes.

Também podem ocorrer rate_limited (429, excesso de requisições) e server_error (500).

Exemplo cURL

curl -X POST https://geradorln.lovable.app/api/public/key/validate \
  -H "Content-Type: application/json" \
  -d '{"key":"A0281N-IQM1B7SIB--U1M81","hwid":"ANDROID_ID"}'

Exemplo Android (Kotlin)

Usa OkHttp e JSONObject. Execute fora da thread principal (corrotina, Thread ou enqueue).

val hwid = Settings.Secure.getString(contentResolver, Settings.Secure.ANDROID_ID)

val body = JSONObject()
    .put("key", userKey)
    .put("hwid", hwid)
    .toString()

val req = Request.Builder()
    .url("https://geradorln.lovable.app/api/public/key/validate")
    .post(body.toRequestBody("application/json".toMediaType()))
    .build()

client.newCall(req).execute().use { res ->
    val json = JSONObject(res.body!!.string())
    if (json.getBoolean("valid")) {
        // Libera o app; use seconds_left para o contador
    } else {
        when (json.getString("reason")) {
            "invalid_key"   -> showError("Key inválida")
            "paused"        -> showError("Key pausada")
            "expired"       -> showError("Key expirada")
            "hwid_mismatch" -> showError("Key já usada em outro aparelho")
            else            -> showError("Erro ao validar")
        }
    }
}

Reset HWID

No painel, a ação Reset HWID desvincula o aparelho atual da key. A próxima chamada válida a /validate vincula o novo aparelho.

O tempo da licença não é reiniciado: activated_at e expires_at continuam os mesmos. Até o novo aparelho chamar /validate, o /status responde hwid_mismatch.
